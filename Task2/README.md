# Пояснения по выполнению задания
В задании одновременно требуется загрузить данные о пользователях, данные значений датчиков телеметрии, сформировать витрину, а так же реализовать
получение отчета в разрезе пользователя и так, чтобы каждому пользователю были доступны данные только его данные. Поэтому
я решил в качестве данных о пользователях использовать таблицу user_profiles из предыдущего задания, в которой записи создаются
при авторизации пользователя, если он там отсутствует (данные профиля берутся из JWT-токена). Пример данных телеметрии я нашел в репозитории и
значительно их сократил, сделав привязку с к пользователям из user_profiles. Таким образом у меня получилась CRM DB, состоящая из 2 таблиц:
user_profiles и emg_sensor_data. Эти таблицы в итоге являются источниками для ETL-процесса, реализованного в пайплайне (DAG) Apache Aitflow.


Итого сделано:
1. Реализован DAG в Apache Airflow (olap/dags), загружающий данные CRM DB из таблиц user_profiles и emg_sensor_data в соответствующие таблицы
в ClickHouse
2. В ClickHouse реализована витрина данных в виде представления, объединяющего таблицы user_profiles и emg_sensor_data
3. Перед каждой загрузкой в таблицы они очищаются. Так сделано для простоты (это ведь учебный кейс). Конечно в реальном ETL-процессе так обычно не делают, но опять же от конкретной задачи зависит.
4. Данные в витрине дополнительно не агрегируются, так как в задании не описаны критерии для этого.  
5. Реализован сервис отчетов reports-service (/api/report), который получает отчет для авторизованного пользователя из ClickHouse (авторизация проверяется 
по JWT-токену, передаваемому в заголовке запроса) 
6. Переиспользован сервис авторизации bionicpro-auth, который реализован в рамках предыдущего задания. Сервис инкапсулирует логику
SSO (взаимодействует с Keycloak), управляет пользовательскими сессиями, создает профили пользователей (при первой авторизации),
а так же проксирует запросы от фронтенда к сервису отчетов
7. Доработан сервис frontend: реализовано получение отчета и его выгрузка в формате excel. Для упрощения период для отчета жестко задан в
коде (он охватывает диапазон дат в тестовом датасете). Что касается пользователя, то его сервис отчетов извлекает из JWT-токена.
