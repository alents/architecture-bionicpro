# Пояснения по выполнению задания
В репозитории, ссылка на который дана в проектной работе, уже имеется csv с данными датчиков телеметрии, агрегированными в разрезе клиентов.
Я решил его сделать источником данных для ETL-процесса (DAG) вместо того, чтобы отдельно поднимать базу данных API сбора датчиков,
импортировать данные в нее, а потом уже использовать в качестве источника в ETL. Я считаю, что этого достаточно в рамках задания,
где необходимо показать понимание разработки и настройки процесса ETL в Apache Airflow. Учитывая то, что далее в задании имеется
требование показывать данные отчета только в разрезе пользователя, который его запрашивает, я адаптировал данные csv: оставил только
30 записей и у оставшихся записей изменил user_id так, чтобы они ссылались на идентификаторы пользователей таблицы user_profiles
(данная таблица содержит профили пользователей их привязку к учетным записям в Keycloak через subject_id: записи в эту таблицу попадают
при первой авторизации пользователей (это было реализовано в задании 1)).   
Данные о профилях пользователей я не стал загружать отдельно в ClickHouse, так как это не имело практического смысла, учитывая, что
нужно было реализовать отчет для получения клиентами только своих данных - все необходимое уже есть в таблице emg_sensor_data.

Итого сделано:
1. Реализован DAG в Apache Airflow (olap/dags), загружающий данные из источника csv с телеметрией датчиков в разрезе клиентов
2. Реализован сервис отчетов reports-service (/api/report), который получает отчет для авторизованного пользователя из ClickHouse (авторизация проверяется 
по JWT-токену, передаваемому в заголовке запроса) 
3. Переиспользован сервис авторизации bionicpro-auth, который реализован в рамках предыдущего задания. Сервис инкапсулирует логику
SSO (взаимодействует с Keycloak), управляет пользовательскими сессиями, создает профили пользователей (при первой авторизации),
а так же проксирует запросы от фронтенда к сервису отчетов
4. Доработан сервис frontend: реализовано получение отчета и его выгрузка в формате excel. Для упрощения период для отчета жестко задан в
коде (он охватывает диапазон дат в тестовом датасете). Что касается пользователя, то его сервис отчетов извлекает из JWT-токена.
